# CONTEXTO_REPORTES.md

## 1. Propósito

Resume los principales tipos de informes y artefactos utilizados.

La **plantilla oficial del repositorio siempre prevalece**.

# 2. Informe cualitativo de estudiantes / focus group

## Objetivo
Comprender la experiencia vivida a lo largo del Journey.

## Estructura habitual
1. Alcance y corpus
2. Síntesis de la experiencia
3. Temas emergentes
4. Lectura temporal del Journey
5. Insights prioritarios
6. Momentos de verdad
7. Tensiones
8. Fortalezas a proteger
9. Fricciones y necesidades
10. Preguntas abiertas
11. Lectura central / conclusión
12. Triangulación, cuando exista evidencia adicional

# 3. Informe cualitativo de Coordinación

## Objetivo
Comprender cómo se sostiene operacionalmente la experiencia.

## Estructura utilizada
1. Alcance
2. Lectura general desde Coordinación
3. Insights principales para el Journey
4. Fortalezas a proteger
5. Momentos críticos
6. Conclusión
7. Diferencias entre programas cuando una coordinación gestiona más de uno

## Insight de coordinación
**Evidencia → Lectura para experiencia → Implicancia.**

# 4. Informe cualitativo de Dirección

## Objetivo
Comprender la experiencia desde estrategia, gobernanza y propuesta académica.

## Regla crítica
Abrir siempre la plantilla oficial, por ejemplo:
`PLANTILLA_INFORME_DIRECTOR.docx`

y replicar su arquitectura vigente.

## Cuando una persona dirige dos programas
No duplicar artificialmente el informe.

Distinguir:
**COMÚN**
**PROGRAMA A**
**PROGRAMA B**

# 5. Informe parcial

Cuando la entrevista no termina:

### Debe indicar
**VERSIÓN PARCIAL / PENDIENTE DE COMPLEMENTO.**

### Debe incluir
- qué sí se abordó;
- qué falta;
- preguntas pendientes;
- vacíos en Journey;
- limitación de conclusiones.

### Al recibir respuestas escritas
Integrarlas dentro de las secciones existentes.
No tratarlas únicamente como anexo.

# 6. Triangulación de programa

Con:
- Focus / estudiantes;
- Coordinación;
- Dirección;

buscar:
- convergencias;
- brechas de percepción;
- complementariedad;
- contradicciones.

# 7. Service Blueprint

## Objetivo
Conectar experiencia visible con sistema institucional.

## Capas
- estudiante;
- necesidad;
- momentos críticos;
- actores;
- áreas;
- procesos;
- sistemas/recursos;
- riesgos.

## Evolución recomendada
Agregar:
- input;
- tarea;
- output;
- destinatario;
- owner;
- señal de cierre;
- handoff;
- indicador.

# 8. Brochure / Guía del Journey

## Público
Estudiante.

## Debe mostrar
- transformación esperada;
- recorrido;
- expectativas;
- momentos críticos;
- mapa de ayuda;
- proyecto final;
- cierre;
- Alumni.

## No debe mostrar
- organigrama;
- áreas involucradas como lista interna;
- problemas backstage;
- soluciones aún no implementadas como promesa.

## Convenciones
`[VALIDAR]`
`[COMPLETAR]`

# 9. Taller para áreas / Blueprint colaborativo

## Secuencia
0. Bienvenida
1. Blueprint base
2. ¿Dónde participa mi área?
3. ¿Qué hacemos realmente?
4. La posta / handoffs
5. ¿Dónde se rompe?
6. Priorización
7. Cierre

# 10. Reglas de redacción

Evitar:
- juicios personales;
- culpabilización;
- causalidades no demostradas;
- universalizar episodios puntuales.

Preferir:
- “aparece como”;
- “desde esta perspectiva”;
- “la evidencia sugiere”;
- “requiere triangulación”;
- “se observa una posible tensión”.
